How this works, in four honest steps

  1. Pick one card below. Image, sound or video. One limb is a complete product — you are not buying the suite, and nothing else on the portal changes.
  2. Copy the agent brief. It names the engine, the exact weights, the folder each file goes in, the command, and what it must prove before it reports success. Paste it into Claude Code, Codex, Grok, or any agent with a shell on your PC.
  3. Your agent installs it. ComfyUI, the weights, the workflow, then the bridge on 127.0.0.1:8191 (image), :8192 (sound) or :8193 (video). It reports what it measured, not what it hopes.
  4. The portal lights up. This page and the portal's LOCAL LIMBS module probe that port and, when it answers, generate on your machine with the file rendered in the page. Chrome will ask once for local network access — that is the page reaching your own PC, and it is the one permission this needs. Refuse it and the bridge still works in its own window (127.0.0.1:8191), which needs no permission at all.

Only want pictures? Then only install pictures.

The full LYGO LLM Console is the everything-build: chat on your own GGUF, skills, the image suite and the USB version. It is the right answer if you want a local chat brain. It is the wrong answer if all you want is better images than a free API tier gives you — that is one model, one folder and one bridge, and this page is the short path.

Two paths, same honesty: A — do nothing, paste an API key in the portal, and the vendor's model draws. B — install a limb here, and your own card draws with no per-picture bill. Neither is a subscription, and neither hides which one answered: every image the page makes carries its route.

What we do and do not claim

  • No mirror, no re-host. Every weight link goes to the official Hugging Face repository. We do not serve model files, and we do not repackage licences we cannot ship.
  • Stub mode is not a demo of the model. The bridge ships a --backend stub that writes a gradient, a sine tone and a test clip. It exists so you can prove the page ↔ limb wiring before a 20 GB download. /health always says which backend answered — if it says stub, no model ran.
  • Your machine stays yours. The bridge binds 127.0.0.1 only. Nothing is uploaded, no account exists, and the portal cannot reach the limb unless the limb is running.
  • The browser is a gate, not a bug. A public HTTPS page calling a program on your own PC is a Local Network Access request: Chrome asks, and if it is refused the page shows blocked by this browser rather than pretending the limb is missing. Every card links to the bridge's own window as the fallback, so a strict browser costs you the portal's paint job, never the engine.
  • Hardware numbers are tiers, not promises. 12 GB of VRAM is comfortable for image and video at 720p; 8 GB works with quantized files and one job at a time; no NVIDIA card means use the API route, not this page.
